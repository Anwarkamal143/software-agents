# Run errors are retried, fail Verdicts Bounce, and only a human starts a new Attempt

Every failure falls into one of five kinds, each with one fixed response. **Transient** errors (API overload or 5xx, network blips, GitHub 5xx or 429) are retried with backoff, three times over about five minutes, without counting. A **fail Verdict** (`stage-failed`) Bounces, as before. A **Run error** (`stage-errored`, `data.reason` one of `crash`, `sdk-error`, `invalid-result`, `timeout`, `budget`) is retried and counted. **Needs judgement** (Bounce cap or repeated root cause, three Guard denials, a failed Pre-push check, an issue changed since approval, retries run out) goes to a Human request. A **Factory fault** (Job store unwritable, bad credentials, App uninstalled, Sandbox unavailable) pauses or stops the whole Factory. We rejected treating every failure alike and retrying until a cap: it spends money repeating an expensive or deterministic failure, and it lets the Factory loop on its own. So a hard Budget hit is never retried, a repeated failure goes to a human early, and the Orchestrator never starts a new Attempt by itself.

## Consequences

- A Stage gets up to 2 retries per Attempt, resumes included. `crash` / `sdk-error` resume the session once, then start fresh; `invalid-result` resumes with the schema errors as a correction turn; `timeout` starts fresh; `budget` goes straight to a human with the cost and turns so far. A retry that hits the same reason in the same place (same failing command or schema error) skips the remaining retries. Retries run out → waiting, with `/approve` for one more try or `/cancel`; never a silent failure.
- Stuck detection: the wall-clock Budget (default 30 minutes) or 10 minutes with no SDK message aborts the session as `timeout`. Waiting, paused and queued Jobs are never stuck; a Job queued over a day only warns in `factory status`.
- Restart: a lock file allows one Orchestrator. At startup it replays the Event log, marks unfinished Stage runs `stage-interrupted` (then resume once or rerun), leaves plan-limit-parked runs until `resetsAt`, and deletes Working copies of no live Job.
- Ending a Job: cancelled closes the PR with a comment, deletes every Attempt's branch and the Working copy, removes the ready label and sets `factory:cancelled`; failed turns the PR into a draft, keeps branches and the Working copy for 7 days, and says how to retry (re-label or `factory retry`); merged deletes branches and the Working copy.
- Housekeeping sweeps at startup and hourly (7-day Working copies, 30-day Transcripts and artifacts except merged Evidence, orphans, failed branch deletions) and records one `housekeeping-ran` event.
- If the Job store can't be written, the Orchestrator stops. If GitHub is down, Stage runs carry on and merges wait. A config change that fails `factory config check` is rejected and the old config stays.
- Adds `stage-errored` and `housekeeping-ran` to the event types of ADR 0009.
